## Verification and remaining gates

A full candidate must be built from authorized input with the existing signing identity; do not use the historical controls-only repack. The new local verifier checks archive completeness, alignment, the actual certificate and manifest, version continuity, the coordinated Java/ELF/asset layout, and that the experimental browser OAuth path is not enabled or declared. It never signs, installs or publishes anything.

The third-party OAuth prototype has been retired in the proposed source: its identifiers and network exchange are removed, the callback is disabled, and old enable flags cannot restore it. Normal game sign-in is not deliberately replaced by this path; real login is still unverified. The historical full release workflow remains disabled. The dedicated **PGS v0.0.3 — full candidate validation** workflow requires an explicit manual confirmation of authorized, hash-pinned input, the existing signing configuration and the unchanged issuance ledger. It builds and validates only in an isolated runner, uploads only verification receipts, and never publishes or distributes the APK. Use an authorized private/local environment for any eventual candidate handoff. No new signing key or external APK is required for the synthetic tests.

A successful static verification is not device acceptance. Keep any subsequent candidate unpublished until the existing PGS installation's certificate and versionCode are checked, the in-place upgrade is tested without uninstalling, and account access, settings, joystick, and saved data are verified. Issues #24 and #38 remain open.

The first manual candidate validation (run 46013589321) stopped in a version-override regression before accessing signing configuration. The regression now explicitly tests both the primary and fallback environments; routine CI also runs the suite with the proposed candidate version. A new manual run from the reviewed main revision is required after approval; retrying the old run would reuse the old commit.
